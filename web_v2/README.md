# CP (CRM Pioneer) 이커머스 고객 진단 대시보드 · 2기

로컬호스트 전용 Flask 웹 대시보드입니다. `weekend/` 분석 결과(r1-1 ~ r6-1)를 CRM 진단 · 실행 화면으로 보여 줍니다.

## 실행

```bash
pip install flask            # 최초 1회
python crm_pj/web_v2/app.py  # http://127.0.0.1:5001  (1기는 python crm_pj/web/app.py → 5000, 나란히 비교)
```

선행 조건: `weekend/crm_db/*.pkl`이 있어야 합니다 (weekend/r1-1 ~ r6-1 실행).

## 화면

| 경로 | 메뉴 | 내용 |
|---|---|---|
| `/` | 첫 화면 | 로고 · 시작 버튼 · 가명 안내 |
| `/overview` | ① Executive 요약 · WHY | AARRR 다섯 단계 진단, Vanity vs Actionable, 가치 × 위험 매트릭스, 운영 규칙 4개 |
| `/journey` | ② 여정·퍼널 · WHERE | 여정 지도, 180일 구매 단계 퍼널, 주별 두 번째 구매 확률, 온보딩 리마인드 규칙, 월별 코호트 |
| `/simulator` | ③ 실행 플랜 · HOW | 매장 성격, 캠페인 플레이북 5개, 공통 원칙, 실험 설계 |
| `/actions` | ④ Action Queue · WHAT | 캠페인 · 가치 등급 · 이탈 위험 필터, 우선순위 명단, 발송용 CSV |
| `/customer?q=이름또는ID` | ⑤ Customer 360 · WHO | 등급 · 위험 · 여정 단계, 추천 캠페인, 다음 발송, 성공 지표 |

## 데이터와 가정

- 분석은 익명 `customer_id`로 수행하고, 화면에서만 가명을 매핑합니다(`data/names.csv`, `data/make_names.py`로 재생성).
- 매출은 GST 제외. 원가가 없어 이익(LTV/CAC, 온보딩 1인당 예산 상한)은 마진 30%로 가정합니다.
- '신규'는 생애 첫 구매가 아니라 2019년 관측 첫 구매입니다 (가입기간 12개월 초과 고객 78%).
- 캠페인 성과는 대상의 절반을 보류군으로 두고 90일 재구매율로 비교합니다.

## 2기에서 바뀐 점 (1기 `web/` 대비)

| 화면 | 변경 |
|---|---|
| ① Executive 요약 | AARRR 5단계 칸(값 · 정의 · 비교 숫자 · 상태 태그로 통일), Vanity vs Actionable 차트(월 매출 vs 첫 구매 월별 90일 전환) |
| ② 여정·퍼널 (신규) | 여정 지도, 구매 단계 퍼널, 주별 두 번째 구매 확률, 월별 코호트 리텐션 → 리마인드 D+7·D+30 근거 |
| ④ Action Queue | Top100 대기열·실행 규칙 7개 대신 캠페인 필터, 다음 발송 열 |
| ⑤ Customer 360 | 배지는 등급·위험·여정 단계만, 추천 캠페인과 다음 발송 시점 |
| ③ 실행 플랜 (1기 So What? 대체) | 매장 성격 → 여정 단계별 캠페인 플레이북(대상·시점·채널·메시지·혜택·지표) → 실험 설계(MDE). 가정값 의존이 큰 ROI 시뮬레이터는 제외하고 온보딩 1인당 예산 상한만 남김 |

- 두 번째 구매 타이밍은 첫 구매 후 180일 이상 관측된 고객만 사용합니다(늦게 들어온 고객의 중도절단 방지).
- 기존 고객 실험의 기준값은 이탈 모형 검증 시점(10/2 점수 → 10/3~12/31 관측)의 같은 위험 등급 재구매율입니다.

메뉴 순서는 진단(① 요약) → 원인(② 여정·퍼널) → 처방(③ 실행 플랜) → 명단(④ Action Queue) → 개별 고객(⑤ Customer 360)입니다.
